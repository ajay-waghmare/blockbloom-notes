## Emergency Incident: Remote Config Force-Update Lockout (Resolved)
- **Incident**: Players and local test builds received a blocking, non-dismissible full-screen dialog ("Update required � This version of Block Bloom can no longer be played. Please update to keep your progress and carry on.").
- **Root Cause**: In Firebase project `block-bloom-31b39`, Remote Config parameter `min_supported_version_code` had been set to `23` on 19 Oct. `UpdateRules.isBlocked(required)` blocked every active client with `versionCode < 23` (including legacy players on vc22 and older local builds).
- **Resolution**:
  - `min_supported_version_code` reset from `23` back to `0` in Firebase Remote Config (Version 2 published by Ajay at 2026-10-20 18:03 UTC).
  - All clients and test devices immediately unlocked on subsequent launch/resume.
  - Built fresh debug APK for vc24 (`1.12.1-debug`) at `~/.build-blockbloom/app/outputs/apk/debug/app-debug.apk` and copied to `Downloads/BlockBloom-vc24-debug.apk`.
- **Takeaway / Rule**: `min_supported_version_code` must ALWAYS remain `0` (fail-open) unless an active emergency kill-switch is strictly needed for a known corrupted client build. Never pull this lever as a release nudge.
